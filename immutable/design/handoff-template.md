# design Step 4 handoff-note template

This file is the markdown template the `design` skill renders in Step 4.2.
Placeholders use single-brace mustache (`{name}`); the skill substitutes them
during rendering.

The leading `### TEMPLATE START` and trailing `### TEMPLATE END` markers below
are stripped when the skill writes the note. Everything between them is the
actual document body.

## Section authoring notes

| Placeholder | Source step | Format |
|-------------|-------------|--------|
| `{title}` | Step 1 / 4.1 | Short feature name; `Refactor: {area}` in no-pitch mode |
| `{iso_date}` | Skill runtime | `YYYY-MM-DD` |
| `{branch}` | git probe | Branch name |
| `{pitch_path}` | Step 1.3 | Relative path inside the spec repo (e.g., `pitches/cart/2026-04-15-review-request.md`); or `(none — refactor)` |
| `{pitch_domain}` | Step 1.3 | Pitch frontmatter `domain:` value; or `_internal` for refactors |
| `{pitch_summary}` | Step 1.3 | 2-3 sentences summarizing the pitch — NOT a full restatement. Plan-review skills read the pitch directly. |
| `{files_to_touch}` | Step 2.1 | Bullet list, each line `- path/to/file.ext — one-line role` |
| `{existing_to_reuse}` | Step 2.2 | Bullet list of abstractions / services / patterns. Empty list is OK if truly nothing relevant — say so explicitly. |
| `{activation}` | Step 3.1 | Three sub-bullets: Version, Hidden paths, Live trigger. |
| `{dependencies}` | Step 3.2 | Bullet list. Empty list ↔ "None known." |
| `{module_placement}` | Step 3.3 | Module path + cross-module dependencies + new-module note (if any). |
| `{open_questions}` | Step 3 | Bullet list. Empty ↔ "None — proceed to plan-review." |

## Refactor-mode adjustments

When the user takes the no-pitch path in Step 1.4 (internal refactor / infra),
adjust two sections:

- `{pitch_summary}`: replace with one sentence describing the refactor's intent
  (e.g., "Extract repeated cart state computation into a single ViewModel.").
- `{activation}`: replace with "N/A — internal change, no user-visible toggle."

Plan-review-ceo will detect the `pitch: (none)` line and skip the pitch-grounded
review questions, focusing on architecture and code quality.
