# office-hours Phase 4 design-doc template

This file is the markdown template the `office-hours` skill renders in Phase 4.2.
Placeholders use single-brace mustache (`{name}`); the skill substitutes them
during rendering.

When the skill writes the file at `.claude/immutable/office-hours/{slug}.md`,
the leading `### TEMPLATE START` and trailing `### TEMPLATE END` markers below
are stripped. Everything between them is the actual document body.

## Section authoring notes

For each placeholder above, the skill captures these from earlier phases:

| Placeholder | Source phase | Format |
|-------------|--------------|--------|
| `{title}` | Phase 1 (free-text + slug) | One short sentence (<=70 chars) |
| `{iso_date}` | Skill runtime | `YYYY-MM-DD` |
| `{branch}` | Phase 1 git probe | Branch name as-is |
| `{mode}` | Phase 1.3 | `product` / `tooling` / `refactor` / `spike` |
| `{supersedes}` | Phase 1.2 (existing prior file?) | Filename only, e.g. `2026-04-15-foo.md`. Drop the `Supersedes:` line if first |
| `{problem}` | Phase 1 + Phase 2 | 1-2 paragraphs |
| `{context}` | Phase 1.2 | Bullet list of relevant code areas / patterns |
| `{premises}` | Phase 2 | Numbered list, each ending in `(confirmed)` or `(disputed → revised)` |
| `{approach_a}` ... `{approach_c}` | Phase 3.2 | Each follows the per-approach format (Summary / Effort / Risk / Pros / Cons / Reuses) |
| `{approach_a_name}` etc. | Phase 3.2 | Short name from the approach |
| `{recommended}` | Phase 3.3 | 2-4 sentences naming the chosen approach + rationale |
| `{files}` | Phase 1 + Phase 3 | Bullet list of file paths with one-line descriptions |
| `{edge_cases}` | Phase 3 | Bullet list — edge case + how the recommended approach handles it |
| `{distribution}` | Phase 3 (if new artifact) | Sub-section with build/publish path. Drop the section header if the deliverable is internal-only. |
| `{open_questions}` | Phase 2 + Phase 3 | Bullet list. If empty, write "None — proceed to /immutable:prd." |
